# 【実録】非エンジニアの私が、Claudeに「毎日の定型業務」を丸ごと任せるまで｜4つのファイルで仕組み化する手順

## はじめに：AIを使っているのに、なぜ仕事が減らないのか

「AIを使ってください」と会社で言われた。
ChatGPTも何度か使ってみた。

でも、仕事は減っていない。

質問すると、それらしい答えは返ってきます。
でも結局、その答えをコピーして、自分の仕事に合わせて直すのは自分。
次の日も、また同じ説明をAIにするところから始まる。

私もずっとそうでした。

原因はシンプルです。
**AIに「質問」していただけで、「仕事を任せて」いなかった**からです。

この記事では、エンジニアではない私が、
Claude（クロード）に毎日の定型業務を覚えさせて、
「調べる → 判断する → 作る → 確認する → 直す」まで任せられるようになった手順を、全部書きます。

## 1. 「質問」と「任せる」の違い：仕事を5工程に分ける

どんな仕事も、だいたい5つの工程に分けられます。

1. **リサーチ**：必要な情報を集める
2. **判断**：何をどうするか決める
3. **制作**：文章・資料・表を作る
4. **確認**：間違いがないかチェックする
5. **改善**：指摘を受けて直す

ChatGPTに「質問」しているとき、AIが手伝っているのは③の制作だけです。
残りの4つは、全部あなたがやっています。だから楽にならない。

「任せる」とは、**5工程をまとめて渡すこと**です。
そのために必要なのが、次の2つ。

- AIが **ファイルを読んで、書いて、保存できる** 環境
- AIが **あなたの仕事のルールを覚えている** 状態

前者が Claude Code や Claude の Cowork（デスクトップアプリで、パソコンのファイルを扱える機能）。
後者が、この記事の中心になる「4つのmdファイル」です。

## 2. 最初に任せる仕事の選び方

いきなり大きな仕事を任せると失敗します。
最初の1つは、次の **4つすべてに当てはまる仕事** を選んでください。

| チェック | 質問 |
|---|---|
| □ 繰り返し | 週に1回以上やっている？ |
| □ 型がある | 毎回だいたい同じ手順・同じ形式？ |
| □ 材料がある | 元になるデータやメモがファイルで手元にある？ |
| □ 確認できる | 出来上がりが正しいか、自分で5分以内に見てわかる？ |

おすすめの1つ目は **議事録** です。
材料（メモや録音の文字起こし）があり、型があり、確認もしやすいからです。

【要記入：自分が最初に任せた仕事と、それを選んだ理由】

## 3. 仕組みの正体：4つのmdファイル

「md」はテキストファイルの一種です。メモ帳で開けます。
Claude Code は、作業フォルダにある `CLAUDE.md` というファイルを、**作業を始めるたびに自動で読みます**。

つまり、ここに仕事のルールを書いておけば、
**毎回同じ説明をしなくてよくなります**。

私は、役割ごとに4つのファイルに分けています。

| ファイル | 中身 | たとえると |
|---|---|---|
| CLAUDE.md | 仕事のルール・手順・禁止事項 | 業務マニュアル |
| knowledge.md | 自分や会社の知識（用語、取引先、決まりごと） | 引き継ぎ資料 |
| references.md | 「これが正解」という過去の成功例 | お手本ファイル |
| learn.md | 過去のダメ出しと、直したこと | 反省ノート |

ポイントは **learn.md** です。
AIに直してほしいことを伝えたら、それを必ずここに書かせる。
すると同じミスを2回しなくなります。
**使うほど、あなたの仕事に詳しくなっていく**仕組みです。

CLAUDE.md には、たとえばこう書きます。

```
# 議事録作成のルール
- 最初に knowledge.md と learn.md を読む
- 形式は references.md の「議事録_お手本」と同じにする
- 決定事項・宿題（担当者・期限）・次回日程を必ず分ける
- 発言者の名前は knowledge.md の社員一覧の表記に合わせる
- わからない箇所は推測せず【要確認】と書く
- 指摘を受けたら learn.md に1行で追記する
```

4つのテンプレートは購入特典に全文載せています。

## 4. 実践：1つ目の仕事を任せるまで（議事録の例）

**ステップ1：作業用フォルダを1つ作る**
デスクトップに「議事録AI」などのフォルダを作ります。
ここに4つのmdファイルと、会議メモを入れていきます。

**ステップ2：お手本を1つ入れる**
過去に自分で作った「いちばん良い議事録」を references.md に貼ります。
これがあるだけで、出来上がりの形式がほぼ揃います。

**ステップ3：knowledge.md に「よく出てくる言葉」を書く**
社内の略語、プロジェクト名、メンバーの名前の書き方など。
最初は5行でかまいません。

**ステップ4：Claude に頼む**
Claude Code（または Cowork）でこのフォルダを開いて、こう伝えます。

```
「会議メモ_0929.txt」から議事録を作って。
CLAUDE.md のルールに従って、「議事録_0929.md」として保存して。
```

**ステップ5：5分で確認して、ダメ出しする**
直してほしいところは、自分で直さずに **Claude に言葉で伝えます**。

```
宿題の期限が抜けている。メモに期限がない場合は【要確認】と書いて。
この指摘を learn.md に追記して。
```

これを3〜5回くり返すと、ほとんど直すところがなくなります。

【要記入：自分の場合、何回目で手直しがほぼ不要になったか】

## 5. 精度を上げるコツ

- **お手本は多いほど強い**：良い成果物ができたら references.md に追加する
- **ルールは「〜しない」より「〜する」で書く**：「長くしない」より「3行以内にする」
- **一度に1つの仕事だけ**：議事録が安定してから、次の仕事に広げる
- **わからないことは【要確認】と書かせる**：AIがそれらしく推測して間違えるのを防ぐ

## 6. よくある失敗5つと対処法

| 失敗 | 対処 |
|---|---|
| いきなり大きな仕事を任せて、ぐちゃぐちゃになる | チェックシートの4条件を満たす小さな仕事から |
| 自分で直してしまい、AIが学ばない | 直すのではなく「言葉で指摘 → learn.md に追記」 |
| CLAUDE.md が長くなりすぎる | 仕事ごとにフォルダを分ける。1ファイル1画面程度が目安 |
| 社外秘の情報をそのまま入れてしまう | 会社のAI利用ルールを先に確認。個人情報は伏せ字にする |
| 出来上がりを確認せずに提出する | 最後の確認は必ず人がやる。AIは「下書き担当」 |
